# تطبيق الموبايل (Android + iOS) — Flutter

تطبيق واحد مربوط بنظام الكاشير (`restaurant-pos`) عن طريق الـ API، وبيفتح الشاشات حسب نوع الحساب:

| الحساب | اللي بيظهر |
|---|---|
| **عميل** (يسجل بنفسه برقم الموبايل) | المنيو، السلة، طلب دليفري أو استلام، تتبع حالة الطلب لحظياً، طلباتي، تعديل العنوان |
| **كاشير** | شاشة الكاشير (صالة/تيك أواي/دليفري، طاولات، خصم، دفع وباقي)، الطلبات (تحصيل، تغيير حالة، تعيين طيار، فاتورة) |
| **مدير / مالك** | التقارير (مبيعات، ربح تقديري، غير محصل، حسب النوع وطريقة الدفع، الأكثر مبيعاً، الطيارين، بالفترة) + كل شاشات الكاشير |
| **طيار** | بدء/إنهاء الشيفت، إرسال موقعه الحالي (GPS) للمطعم، خريطة بموقعه وأماكن العملاء، مراحل كل طلب: استلمت ← وصلت ← تم التسليم أو تعذر التسليم بسبب، اتصال واتجاهات، الكاش اللي معاه |

التطبيق **عربي وإنجليزي**: زر **EN / ع** في الشريط العلوي، والاتجاه بيتقلب تلقائياً. أول مرة بيفتح بلغة الموبايل، وبعدها بيفتكر اختيارك. أسماء المنيو بتيجي من السيرفر باللغة المختارة. نصوص الإنجليزي في `lib/core/translations_en.dart` (المفتاح هو النص العربي).

على التابلت شاشة الكاشير بتتقسم نصين (المنيو + الطلب) زي الكاشير على الويب.

## تطبيق الطيار المنفصل

نفس الكود بيطلع **تطبيقين على أندرويد** يتثبتوا جنب بعض:

| التطبيق | الاسم على الموبايل | الأمر |
|---|---|---|
| الكامل (عميل + موظفين) | كاشير المطعم | `flutter build apk --flavor full` |
| الطيار فقط | طيار المطعم | `flutter build apk --flavor driver -t lib/main_driver.dart` |

تطبيق الطيار بيفتح على صفحة دخول الطيار على طول، ومش بيقبل غير حسابات الطيارين.
وعلى أندرويد لازم تحدد الـ flavor في التشغيل كمان: `flutter run --flavor full` أو `flutter run --flavor driver -t lib/main_driver.dart`.

### تتبع الموقع
- الطيار يفتح **الشيفت** ← التطبيق يطلب إذن الموقع، ويبعت موقعه كل ما يتحرك حوالي 20 متر، ومرة كل دقيقة لو واقف.
- على أندرويد التتبع بيكمل والتطبيق في الخلفية (بيظهر إشعار ثابت "أنت في الشيفت") لحد ما يقفل الشيفت.
- المطعم بيشوف الطيارين على **خريطة الطيارين** في لوحة الويب، وفي تطبيق الكاشير/المدير (تبويب الطيارين)، مع الطلبات اللي مع كل طيار ومرحلتها.
- العميل يقدر يحدد موقعه وهو بيطلب، ويشوف الطيار على الخريطة والطلب في الطريق.
- الطيار يعتبر "غير متصل" لو موقعه متحدثش من 10 دقايق.
- لو التوصيل اتعذر، الطيار بيختار السبب والطلب بيرجع للمطعم بحالة "جاهز" عشان يتعين لطيار تاني.

## المنصة متعددة المطاعم (SaaS)

أول ما التطبيق يفتح بيطلب **كود المطعم** (نفس الكود اللي في رابط لوحة المطعم `/app/{كود}`)، وكل الطلبات بتروح على `/api/{كود}/...`.
- العميل يكتب كود المطعم اللي عاوز يطلب منه، ويقدر يغيره من "تغيير المطعم".
- **نسخة خاصة بمطعم** (باسم المطعم من غير ما العميل يكتب الكود):
  ```bash
  flutter build apk --flavor full --dart-define=API_URL=https://pos.example.com --dart-define=TENANT=burger-house
  ```
- لو اشتراك المطعم منتهي، التطبيق بيعرض رسالة "انتهى اشتراك المطعم".

## ربط التطبيق بالسيرفر

1. ارفع نظام `restaurant-pos` على سيرفر (أو شغله على جهاز في شبكة المطعم: `php artisan serve --host=0.0.0.0 --port=8000`).
2. في التطبيق: أيقونة السيرفر في أول شاشة ← اكتب الرابط (مثلاً `https://pos.example.com` أو `http://192.168.1.10:8000`).
   أو حدده وقت البناء: `--dart-define=API_URL=https://pos.example.com`.

## بناء الـ APK و iOS

### الطريقة الأسهل: GitHub Actions (بدون ما تثبت حاجة)
من تبويب **Actions** في GitHub ← **Mobile apps (Android APK + iOS)** ← **Run workflow** واكتب رابط السيرفر.
بعد ما يخلص، نزّل من **Artifacts**:
- `restaurant-pos-android-apk` ← ملف `app-full-release.apk` (التطبيق الكامل).
- `restaurant-driver-android-apk` ← ملف `app-driver-release.apk` (تطبيق الطيار).
- `restaurant-pos-ios-unsigned` و `restaurant-driver-ios-unsigned` ← نسخ iOS **غير موقعة** (نسخة الطيار على iOS بنفس الـ Bundle ID، فلازم تغيره من Xcode عشان تنشرها كتطبيق منفصل). Apple مش بتسمح بتثبيت أي تطبيق على iPhone من غير توقيع، فمحتاج
  حساب Apple Developer (99$ في السنة) وتوقعه وترفعه على TestFlight / App Store، أو تبنيه من Xcode على Mac لجهازك.

### محلياً
```bash
cd mobile_app
flutter pub get
flutter run --flavor full                     # على موبايل/محاكي متوصل
flutter build apk --release --flavor full --dart-define=API_URL=https://pos.example.com
flutter build apk --release --flavor driver -t lib/main_driver.dart --dart-define=API_URL=https://pos.example.com
flutter build ios --release --dart-define=API_URL=https://pos.example.com   # على Mac فقط
```

> ملحوظة: الـ APK الحالي موقّع بمفتاح debug (مناسب للتثبيت المباشر). للنشر على Google Play اعمل keystore
> واتبع: https://docs.flutter.dev/deployment/android#sign-the-app

```
├── core/cart.dart            # السلة + نفس معادلة الحساب اللي على السيرفر
├── core/models.dart
├── widgets/                  # المنيو، السلة، عناصر مشتركة
└── screens/

    ├── orders/               # الطلبات وتفاصيلها
    ├── owner/                # تقارير المالك
    ├── driver/               # تطبيق الطيار
    └── customer/             # تطبيق العميل
```
