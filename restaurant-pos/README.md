# برنامج كاشير للمطاعم والدليفري (Laravel + Filament + MySQL)

نظام نقطة بيع (POS) للمطاعم: صالة، تيك أواي، ودليفري — مبني على **Laravel 13** و **Filament 5** وقاعدة بيانات **MySQL**، بواجهة عربية (RTL).

## المميزات

- **شاشة الكاشير** (`/admin/pos`): أصناف بالأقسام وبحث، سلة بكميات وملاحظات لكل صنف، خصم (مبلغ أو %)، طرق دفع (كاش / فيزا / محفظة)، حساب الباقي وأزرار فئات سريعة (50/100/200/500).
- **3 أنواع طلبات**:
  - **صالة**: اختيار الطاولة من خريطة ملونة (متاحة/مشغولة). لو الطاولة عليها طلب مفتوح، الأصناف الجديدة تتضاف عليه تلقائياً، ويتحصل الحساب في الآخر.
  - **تيك أواي**: بيانات العميل اختيارية.
  - **دليفري**: البحث عن العميل برقم الموبايل (بيملا الاسم والعنوان والمنطقة تلقائياً)، رسوم توصيل حسب المنطقة، وتعيين طيار.
- **طباعة** فاتورة العميل وبون المطبخ (مقاس 80mm للطابعات الحرارية).
- **إدارة الطلبات**: تبويبات (المفتوحة / اليوم / صالة / تيك أواي / دليفري / غير مدفوع)، تحصيل، تغيير الحالة، تعيين طيار، إلغاء، فلترة بالتاريخ والكاشير والطيار، وإجمالي أسفل الجدول.
- **لوحة التحكم**: مبيعات اليوم مقارنة بأمس، كاش الدرج، عدد الطلبات حسب النوع، الطلبات المفتوحة، المبالغ غير المحصلة، والأصناف الأكثر مبيعاً.
- **الطيارين**: عدد طلبات اليوم والمبلغ المطلوب تحصيله من كل طيار.
- **العملاء**: سجل العملاء وعدد طلباتهم وإجمالي مشترياتهم.
- **صلاحيات**: مدير (كل شيء) وكاشير (شاشة الكاشير + الطلبات + العملاء + الطيارين فقط).
- ضريبة ونسبة خدمة (على الصالة فقط) قابلة للضبط من ملف `.env`.

## التثبيت

المتطلبات: PHP 8.3+، Composer، MySQL 8 (أو MariaDB 10.6+).

```bash
cd restaurant-pos
composer install
cp .env.example .env
php artisan key:generate
```

أنشئ قاعدة البيانات:

```sql
CREATE DATABASE restaurant_pos CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

عدّل بيانات الاتصال في `.env`:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=restaurant_pos
DB_USERNAME=root
DB_PASSWORD=
```

ثم:

```bash
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

افتح: <http://localhost:8000/admin>

| المستخدم | البريد | كلمة المرور |
|---|---|---|
| مدير | `admin@pos.test` | `password` |
| كاشير | `cashier@pos.test` | `password` |
| طيار (تطبيق الموبايل فقط) | `driver@pos.test` | `password` |

> البيانات التجريبية فيها منيو كامل، 10 طاولات، مناطق توصيل وطيارين. غيّر كلمات المرور بعد أول دخول.

## دورة الطلب

`جديد → قيد التحضير → جاهز → مع الطيار (دليفري) → مكتمل` أو `ملغي`

- طلب مدفوع (صالة/تيك أواي) يتقفل "مكتمل" مباشرة.
- طلب "حفظ بدون دفع" يفضل مفتوح لحد ما يتحصل من شاشة الطلبات (زر **تحصيل**)، والطاولة ترجع متاحة تلقائياً بعد الدفع.
- طلب الدليفري يفضل مفتوح لحد ما الطيار يرجع وتغير حالته لـ "مكتمل".

## API تطبيقات الموبايل

تطبيق الموبايل (`../mobile_app`) بيتكلم مع النظام عن طريق `/api` بتوكن Sanctum (`Authorization: Bearer ...` + `Accept: application/json`).

| المسار | مين | الوظيفة |
|---|---|---|
| `GET /api/settings` ، `/api/menu` ، `/api/delivery-areas` | عام | الإعدادات والمنيو ومناطق التوصيل |
| `POST /api/staff/login` | موظف | دخول مدير / كاشير / طيار |
| `POST /api/customer/register` ، `/api/customer/login` | عميل | تسجيل / دخول برقم الموبايل |
| `GET /api/me` ، `POST /api/logout` | الكل | |
| `GET /api/pos/tables` ، `/api/pos/drivers` ، `/api/pos/customers/lookup?phone=` ، `POST /api/pos/orders` | كاشير، مدير | شاشة الكاشير |
| `GET /api/orders?filter=open\|app\|unpaid\|today\|all` ، `GET /api/orders/{id}` | كاشير، مدير | الطلبات |
| `POST /api/orders/{id}/pay` ، `/status` ، `/driver` | كاشير، مدير | تحصيل، حالة (الإلغاء للمدير فقط)، تعيين طيار |
| `GET /api/dashboard?from=&to=` | مدير | تقارير المالك |
| `GET /api/driver/orders` ، `POST /api/driver/orders/{id}/pickup` ، `/delivered` | طيار | طلبات الطيار |
| `GET/POST /api/customer/orders` ، `GET /api/customer/orders/{id}` ، `POST .../cancel` ، `PUT /api/customer/profile` | عميل | الطلب والتتبع |

- الأسعار دايماً بتتحسب على السيرفر من قاعدة البيانات (أي سعر جاي من التطبيق بيتجاهل).
- طلبات تطبيق العملاء بتوصل بحالة **جديد** وبتظهر في تبويب **طلبات التطبيق** في صفحة الطلبات (على الويب والموبايل).
- حساب الطيار: اعمل مستخدم بصلاحية **طيار** من صفحة المستخدمين، واربطه بالطيار من صفحة الطيارين. الطيار ما يقدرش يدخل لوحة الويب.
- `receipt_url` في الطلب رابط موقّع للفاتورة صالح 24 ساعة، بيفتح من الموبايل للطباعة أو المشاركة.
